# Sketch2Shape AI

**TechZephyr 4.0 · IIT Bhubaneswar** — turns a single-view 2D sketch (drawn or uploaded) plus an optional text prompt into a textured, exportable 3D asset (`.glb` / `.obj`).

```
 ┌──────────── Web app (React + Vite + Three.js) ────────────┐        ┌──────────── Google Colab GPU (FastAPI) ────────────┐
 │ Draw canvas / image upload                                 │        │ 1 preprocess   control map (white-on-black scribble)│
 │ CV preprocessing: auto-invert, contrast, denoise,          │  HTTPS │ 2 concept      SD1.5 (DreamShaper-8) + ControlNet   │
 │   threshold, speck removal, auto-crop, 512² centring       │ ─────► │ 3 segment      background removal (rembg)           │
 │ Optional prompt + generation options                       │  jobs  │ 4 shape        Hunyuan3D-DiT (2mini-turbo / 2.0)    │
 │ Pipeline tracker with real per-stage timings               │ ◄───── │ 5 texture      Hunyuan3D-Paint                      │
 │ Three.js viewer (textured/clay/wire/normals)               │  GLB   │ 6 export       trimesh validate → .glb + .obj zip   │
 │ Mesh validation + GLB / OBJ export                         │        └─────────────────────────────────────────────────────┘
 │ Offline engine: silhouette inflation (no GPU needed)       │
 └────────────────────────────────────────────────────────────┘
```

## Running it

### 1. Local TripoSR Engine (RTX 4050 GPU, ~2–4s inference)
Run the local backend server on port 8001:
```bash
run_triposr.bat
# Or: python backend/triposr_server.py
```

### 2. Frontend Web App
```bash
pnpm install
pnpm dev        # opens http://localhost:8443
```
In the web interface:
- **TripoSR (Local GPU)**: Instant neural 3D asset generation directly on your local RTX 4050 GPU.
- **Hunyuan3D-2 (Colab GPU)**: Cloud generative pipeline (open the notebook below and paste the tunnel link).
- **Offline Preview**: Pure client-side closed-mesh inflation in the browser without GPU.

### 3. Cloud Backend (Google Colab, Optional)
1. Open `colab/Sketch2Shape_Hunyuan3D.ipynb` in Colab (`File → Upload notebook`).
2. `Runtime → Change runtime type → GPU` (T4 works; L4/A100 are faster and allow the full model).
3. `Runtime → Run all`. The first run takes about 15–25 min.
4. Copy the `https://….trycloudflare.com` URL printed by step 6.

### 2. Frontend
```bash
pnpm install
pnpm dev        # open the printed localhost URL
```
Click **Connect Colab GPU**, paste the URL, and press **Test**. Then draw or upload a sketch and press **Generate 3D model**.
No GPU? Select the **Offline preview** engine; it builds a closed 3D mesh in the browser.

### API
| Method | Path | Description |
|---|---|---|
| GET | `/health` | GPU, VRAM, models, texture availability |
| POST | `/jobs` | multipart: `image` (PNG), `prompt`, `options` (JSON) → `{job_id}` |
| GET | `/jobs/{id}` | status, current stage, per-stage timings, mesh stats, artifact paths |
| GET | `/jobs/{id}/files/{control\|concept\|segmented\|glb\|obj_zip}` | artifacts |

`options`: `use_controlnet`, `controlnet_scale`, `texture`, `turbo`, `octree_resolution`, `max_faces`, `seed`.

## Limitations
- A single view cannot fully specify hidden surfaces; the back side is inferred by Hunyuan3D.
- Texture painting on a T4 relies on CPU offload and is the slowest stage; disable it for quick demos.
- Quick Cloudflare tunnels are temporary; the URL changes on every restart.
- The offline engine produces inflated, rounded "pebble" shapes. It is a fallback, not a replacement for the GPU model.
- OBJ exported in the browser contains geometry and UVs only; use the Colab `.zip` (OBJ+MTL+PNG) or the GLB for textures.
